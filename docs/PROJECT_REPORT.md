# შესრულებული პროექტის ტექნიკური ანგარიში

**პროექტი:** AeroStudy — Student Task Manager  
**პროგრამა:** Front-end პროგრამირება  
**მოდული:** პრაქტიკული პროექტი  
**ავტორი:** ლუკა მიქაშავიძე

## 1. ამოცანა

დამოუკიდებლად დაიგეგმა Front-end ვებაპლიკაცია, რომლის დანიშნულებაა სტუდენტის სასწავლო ამოცანების ორგანიზება. მომხმარებელს შეუძლია დავალების დამატება, რედაქტირება, წაშლა, დასრულებულად მონიშვნა, ძებნა, გაფილტვრა და დალაგება.

## 2. არქიტექტურა

სამფაილიანი სტრუქტურა: `index.html` განსაზღვრავს სემანტიკურ შინაარსს, `assets/styles.css` — ვიზუალურ სტილსა და რესპონსიულ განლაგებას, `assets/app.js` — ინტერაქტიულობასა და მონაცემთა მართვას. დამატებით შექმნილია SVG favicon.

## 3. HTML5 და ხელმისაწვდომობა

გამოიყენება `header`, `nav`, `main`, `section`, `article`, `footer`, `form`, `label`, `dialog` და სათაურების იერარქია. ინტერაქტიულ ელემენტებს აქვთ `aria-label`, ხოლო სტატისტიკის პროგრესის ზოლს — `progressbar` როლი. დამატებულია კლავიატურით ძირითად შინაარსზე გადასვლის ბმული.

## 4. CSS3 და რესპონსიულობა

CSS Grid ორგანიზებას უწევს მთავარ სექციებს, სტატისტიკის ბარათებს და ფორმის ორ სვეტს. Flexbox გამოიყენება ნავიგაციის, ღილაკების, ფილტრებისა და ამოცანების სტრიქონებისთვის. Media Queries ცვლის განლაგებას 920px, 700px და 370px სიგანეებზე. გამოიყენება სითხისებური ზომები `clamp()`-ით და `max-width` კონტეინერი.

## 5. JavaScript ფუნქციები

CRUD ფუნქციები, სტატუსების შეცვლა, დალაგება, ძებნა, ფილტრაცია, სტატისტიკა, მოდალური ფორმა, მობილური მენიუ და რჩევების კარუსელი. `localStorage` შეიცავს JSON ფორმატის მონაცემებს. მონაცემების არასწორი ფორმატის ან შენახვის პრობლემისას აპლიკაცია შეცდომას ამუშავებს.

## 6. კოდის ოპტიმიზაცია და უსაფრთხოება

- არ გამოიყენება ზედმეტი ბიბლიოთეკები, CDN ან რთული build პროცესი;
- `defer` თავიდან გვარიდებს JS-ის ზედმეტად ადრე შესრულებას;
- DOM-ის ამოცანების ღილაკები ერთ ცენტრალურ Event Delegation-ით მუშავდება;
- შეყვანილი ტექსტი გადის `textContent`-ით, არა HTML ინტერპოლაციით;
- SVG favicon მცირე ზომისაა;
- გამოყენებულია `prefers-reduced-motion`;
- ფუნქციურისა და ადაპტური მუშაობის შემოწმება აღწერილია `TESTING.md`-ში.

**შენიშვნა:** Lighthouse-ის რიცხვითი შედეგები ამ ანგარიშში შეგნებულად არ არის მოგონილი; მათი ჩაწერა შესაძლებელია მხოლოდ რეალური გაზომვის შემდეგ.

## 7. პრობლემები და გამოსავალი

- ბრაუზერში მონაცემთა შენახვის შეზღუდვა — გამოყენებულია `try/catch` და შეტყობინება;
- ცარიელი ფორმის გაგზავნა — ვალიდაცია და ფოკუსის დაბრუნება;
- შემთხვევითი წაშლა — დადასტურების მოთხოვნა;
- ეკრანის სხვადასხვა ზომა — Media Queries;
- მომხმარებლის ტექსტის HTML კოდად აღქმა — `textContent`.

## 8. შეფასების მტკიცებულებები

- სამუშაო გეგმა — `docs/WORK_PLAN.md`;
- სემანტიკური გვერდი — `index.html`;
- დიზაინი და რესპონსიულობა — `assets/styles.css`;
- ინტერაქტიულობა — `assets/app.js`;
- ვერსიების კონტროლი — `.git` ლოკალური ისტორია (საჭიროა სტუდენტის GitHub-ზე ატვირთვა);
- ტესტების სია — `docs/TESTING.md`;
- დოკუმენტაცია — `README.md`;
- პრეზენტაცია — `presentation/AeroStudy_Presentation.pptx`.

## 9. დემონსტრაციის სცენარი

1. ვაჩვენებ გვერდის სტრუქტურასა და რესპონსიულ დიზაინს.
2. დავამატებ ახალ დავალებას, დავარედაქტირებ და მოვნიშნავ შესრულებულად.
3. ვაჩვენებ სტატისტიკას, ფილტრს, ძებნასა და კარუსელს.
4. განვაახლებ გვერდს და ვაჩვენებ `localStorage`-ის მუშაობას.
5. წარვადგენ Git-ის ისტორიას, README-სა და გეგმას.
